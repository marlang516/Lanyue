## 一、发版前（T-3 ～ T-0）

### 1.1 版本与变更

- [ ] **版本三方一致**：`package.json` 的 `version`、git tag（`vX.Y.Z`）、构建产物文件名与 `latest.yml` 中的 `version` 完全一致（含预发布后缀，如 `-beta.1`）。
- [ ] **CHANGELOG 已更新**：`CHANGELOG.md` 顶部新增本版本条目，分类为「新增 / 修复 / 变更 / 安全 / 已知问题」，链接到对应 PR 或 issue。
- [ ] **变更范围已复核**：本版本改动的需求与缺陷均已闭环，QA 验收记录齐全；无未合并的「临时绕过」补丁。
- [ ] **配置差异已确认**：更新通道地址、镜像列表、功能开关与上一版一致（或差异已评审）。
- [ ] **文档同步**：受影响的用户文档 / 架构文档 / 本清单已同步，无遗留「待补」。

### 1.2 质量门禁

- [ ] **lint**：`npm run lint` 通过，无新增告警豁免。
- [ ] **typecheck**：`npm run typecheck` 通过（与 CI 的 `Typecheck (JSDoc)` 同口径）；`vue-tsc` 属 M1 渲染层 TS 迁移范围，M0 不引入，**不得**作为本项判据。
- [ ] **单元 / 契约 / 集成测试**：`npm test` 全绿，无跳过（`skip`）新增用例；契约测试数量与通道方向断言通过。
- [ ] **安全静态检查**：`npm run audit:deps`、`npm run check:dead-deps`、`npm run check:attack-surface` 通过，豁免清单无新增未评审条目。
- [ ] **全量闸**：`npm run verify` 通过（lint + test + 死依赖 + 攻击面 + 图标 + 构建 + asar 冒烟，唯一权威门禁）。
- [ ] **覆盖率**：不低于上一版基线（`src/shared` 90% / `src/main/domain` 80% / 整体 60% 为阶段目标，当前以趋势不下降为准）。
- [ ] **性能**：`npm run bench` 无显著劣化；启动耗时、首屏、内存、包体在预算内（预算见 [`PRODUCTION-UPGRADE.md`](./architecture/PRODUCTION-UPGRADE.md) 第六节）。

### 1.3 构建与产物

- [ ] **构建**：`npm run build` 成功，无构建警告导致的产物缺失。
- [ ] **打包**：`npm run package` 成功（`electron-builder --win --x64`）。
- [ ] **产物自检**：安装包体积符合预算（≤ 120MB）；`resources/app.asar` **必须包含回退产物 `dist/renderer-legacy/**`**，且**不得缺失新层 `dist/renderer/**`**（双轨并行策略见 [`ADR-0001`](./adr/0001-production-upgrade.md)；旧层为回退必备，不得以「冗余」为由剔除）。
- [ ] **asar 冒烟**：`npm run smoke:asar` 通过。
- [ ] **真机裸跑**：双击安装包安装后**裸跑一次**（不加任何命令行旗标），完成「启动 → 搜索 → 播放 → 下载 → 曲库 → 设置」核心链路。
- [ ] **升级路径验证**：从上一版安装包覆盖升级到本版本成功，用户数据（历史、歌单、设置）无损。
- [ ] **产物清单**：本版本产物文件列表已记录（安装包、blockmap、`latest.yml`、校验文件）。

### 1.4 签名与校验

- [ ] **证书可用**：签名证书在有效期内，CI secret `CSC_LINK` / `CSC_KEY_PASSWORD` 已配置且未过期。
- [ ] **代码签名**：安装包与可执行文件已完成 Authenticode 签名（`Get-AuthenticodeSignature` 返回 `Valid`）。
- [ ] **时间戳**：签名带 RFC3161 时间戳，证书过期后签名仍有效。
- [ ] **更新包签名**：`latest.yml` 与更新包签名校验开启，`verifyUpdateCodeSignature` 为真实约束（非空转）。
- [ ] **sha256**：为全部发布产物生成 `SHA256SUMS.txt`（`Get-FileHash -Algorithm SHA256`），哈希与本地复算一致。
- [ ] **指纹公布**：Release 说明中附安装包 sha256 与签名指纹，供用户自行校验。
- [ ] **未签名例外**：若证书未到位，本项必须标记为**阻塞**（不得标 `N/A`），并在 Release 说明中明确「自动更新未启用签名校验」。

### 1.5 草稿 Release

- [ ] **tag 已创建**：`vX.Y.Z` 指向本版本 commit，且已推送远端。
- [ ] **草稿 Release 已创建**：类型为 **draft**，标题与版本号一致。
- [ ] **产物已上传**：安装包、`.blockmap`、`latest.yml`、`SHA256SUMS.txt` 全部上传成功，大小与本地一致。
- [ ] **Release notes**：包含变更摘要、已知问题、升级说明、校验方式（sha256 / 签名）。
- [ ] **未公开发布**：草稿状态保持，未点击 Publish。

## 二、发版中（灰度窗口 T-0 ～ T+24h）

### 2.1 灰度策略

- [ ] **延迟更新**：Release 已可见，但**暂不更新 `latest.yml`**（或启用版本门控），老用户不会立即被推送。
- [ ] **镜像一致性**：所有更新镜像的产物与源站 sha256 一致，无缓存旧文件。
- [ ] **放量计划**：内测 → 小比例 → 全量（若通道支持）；每次放量前确认上一档无阻断指标。

### 2.2 观察指标（24h）

| 指标 | 观察窗口 | 阻断阈值（示例，按项目 SLO 校准） | 结果 |
|---|---|---|---|
| 崩溃率 | 24h | > 0.5% | |
| 更新成功率 | 24h | < 95% | |
| 下载成功率 | 24h | 低于上一版 5% 以上 | |
| 播放取流失败率 | 24h | 显著高于上一版 | |
| IPC 错误率 / 慢调用 | 24h | Top 10 出现新增高频错误 | |
| 用户回退 / 回滚请求 | 24h | > 0 且可复现 | |

- [ ] **监控值守已排班**：灰度窗口内有明确责任人，异常可在 30 分钟内响应。
- [ ] **日志与诊断包可获取**：结构化日志、崩溃转储、诊断包导出功能可用。
- [ ] **阻断条件已确认**：任一阻断阈值命中 → 暂停放量并进入回滚预案（见第四节）。

### 2.3 回滚准备（发版前必须已完成）

- [ ] **上一版安装包已归档**：上一版 `.exe` 与 `.blockmap` 保存在发布归档目录。
- [ ] **上一版 `latest.yml` 已备份**：文件名带版本号（如 `latest-vX.Y.(Z-1).yml.bak`），内容已核对。
- [ ] **回滚脚本可用**：一键回退脚本 / 操作手册已演练，能在 15 分钟内恢复更新通道。
- [ ] **数据兼容确认**：本版本的数据迁移向前兼容，回滚不损坏用户数据（迁移前备份已开启）。

## 三、发版后（T+24h ～ T+7d）

- [ ] **灰度结论**：24h 观察指标全部在阈值内，由发版负责人签字确认后全量放开 `latest.yml`。
- [ ] **更新通道核验**：全量放开后，用上一版客户端实测「检查更新 → 下载 → 安装 → 启动」成功。
- [ ] **用户通知**：发布公告已发出（更新内容、已知问题、回滚说明、校验方式）；必要时站内 / 群公告同步。
- [ ] **文档归档**：`CHANGELOG.md`、发布说明、验签指纹、产物哈希已归档到发布记录。
- [ ] **产物备份**：本版本安装包、`latest.yml`、`SHA256SUMS.txt`、签名证书指纹归档保留（至少保留最近 3 个版本）。
- [ ] **收尾复盘**：记录本次发版的异常、耗时、手工步骤，形成改进项；需流程变更的，同步更新本清单。
- [ ] **监控回归**：发版后 7 天崩溃率与关键失败率达标（崩溃率 < 0.5%、关键失败率 < 1%）。

---

## 四、回滚预案（触发即执行）

**触发条件（任一命中）**：崩溃率超阈值、更新成功率低于 95%、核心链路（播放/下载/启动）不可用、数据损坏、签名/哈希校验失败。

1. **冻结放量**：立即停止 `latest.yml` 更新与灰度放量。
2. **恢复更新通道**：将备份的上一版 `latest.yml` 覆盖回发布目录，确认 `version` 与上一版一致。
3. **校验回退**：用上一版客户端检查更新，确认拉取到的是上一版安装包且 sha256 匹配。
4. **下架问题版本**：将问题 Release 转为 draft 或标记 `Pre-release`，避免新用户下载。
5. **通知用户**：发布回滚公告，说明影响范围、临时规避方式与预计修复时间。
6. **保留证据**：保存问题版本的日志、崩溃转储、诊断包与哈希，供根因分析。
7. **复盘**：24h 内产出事故记录，补齐回归测试，并在下一版 CHANGELOG 中标注。

> 回滚**只回退程序与更新通道，不回退用户数据**；数据迁移必须保证向前兼容，必要时提供数据修复脚本。

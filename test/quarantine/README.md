# test/quarantine — 隔离用例区

本目录**不匹配** `test/*.test.js`，因此不会进入默认测试门禁
（`node --test "test/*.test.js"` 与 `node scripts/test-stable.cjs` 都看不见这里）。

## 为什么要隔离

有些用例**无法在本地稳定运行**，但它们验证的不是业务逻辑，而是外部环境：
真实第三方服务、付费账号、GUI/人工操作、特定硬件。把它们留在默认门禁里只会产生噪声与
「伪失败」，久而久之所有人都学会忽略红灯 —— 那才是真正的损失。

**隔离不是「跳过」的另一种写法。** 判据很窄：

| 可以进来 | 不许进来 |
|---|---|
| 依赖真实网络 / 第三方服务 / 账号 | 只是跑得慢（性能问题必须修，不能隔离） |
| 依赖 GUI、人工点击、视觉比对 | 断言不稳定但能修（要先修稳定性） |
| 依赖特定硬件 / 特定操作系统能力 | 为了让门禁变绿而挪走（掩盖回归） |

## 巡检

默认门禁看不见本目录，必须定期人工跑一遍（建议每季度，或每次发版前）：

```powershell
node --test --test-timeout=60000 "test/quarantine/*.test.js"
```

发现某条已能稳定运行：移回 `test/`，删掉本表中对应行，并在 PR 说明「恢复原因 + 最近一次实跑证据」。

治理背景、根因与推荐跑法见 `docs/process/TEST-STABILITY.md`。
